# Huawei B315s-22 + ESP32: съём CSI

## Почему нужен ESP32

Наш роутер — **Huawei B315s-22** (LTE CPE, Wi-Fi 802.11b/g/n, только 2.4 ГГц, 2 антенны,
адрес `192.168.8.1`, BSSID `14:3c:c3:9d:11:fd`). У него закрытая прошивка HiLink: нет SSH,
нет OpenWrt и нет драйвера, который отдавал бы CSI. Встроенный Wi-Fi ноутбука (Intel AX201)
тоже не умеет отдавать CSI.

CSI измеряется на **приёмнике**, поэтому схема такая:

```
B315s-22 (передатчик) ──Wi-Fi──► ESP32 + ESP32-CSI-Tool ──USB──► esp32_serial_bridge.py ──UDP:5500──► API
```

Роутер ничего не нужно перепрошивать. Приложение берёт только кадры с MAC роутера, а через
HiLink API проверяет, что роутер жив, и читает его модель и настройки Wi-Fi.

## Что купить

Любую плату ESP32 (ESP32-DevKitC / ESP32-WROOM-32) с USB. Плату ставят на другой стороне
комнаты от роутера, так, чтобы между ними проходили люди.

## Настройка роутера (веб-интерфейс http://192.168.8.1)

1. Wi-Fi → **канал зафиксировать** (сейчас «Авто», фактически используется канал 1). Если канал
   переключится сам, ряд CSI оборвётся. Значение канала должно совпадать с `channel` в `src/config/domains.py`.
2. Ширина канала — **20 МГц** (кадры 40 МГц парсер отбрасывает).

## Прошивка ESP32

1. Установить ESP-IDF и клонировать https://github.com/StevenMHernandez/ESP32-CSI-Tool.
2. `cd active_sta && idf.py menuconfig`:
   - SSID/пароль: `GREENHOME` / пароль от Wi-Fi;
   - скорость serial: 921600.
3. `idf.py flash`. Узнать IP платы можно в списке устройств роутера.

## Запуск

```bash
# на хосте (Windows), не в Docker
pip install pyserial
python scripts/esp32_serial_bridge.py --port COM5 --traffic-to <IP_ESP32> --traffic-rate 100
```

`--traffic-to` шлёт маленькие UDP-пакеты на ESP32 через роутер. Каждый такой кадр от роутера
даёт одно измерение CSI, так что частота ≈ `--traffic-rate`. Без этого флага останутся
только beacon-кадры (~10 Гц).

API в Docker слушает `5500/udp` (порт проброшен в `docker-compose.yml`). Для реальных данных
выключите `MOCK_HARDWARE` в `docker-compose.override.yml`.

Проверка: в `GET /health/health` у компонента `hardware` должны расти `connected_routers: 1/1`
и `total_samples` при `success_rate > 0`. Подробная статистика приёмника (принято, отброшено,
чужие MAC, секунд с последнего кадра) лежит в блоке `csi_receiver` метода
`HardwareService.get_status()`. Окно данных — комплексный массив `(1 антенна, 52 поднесущие, 100 кадров)`.

## Параметры

| Переменная окружения | По умолчанию | Назначение |
|---|---|---|
| `ESP32_CSI_UDP_HOST` | `0.0.0.0` | адрес, на котором API принимает строки CSI |
| `ESP32_CSI_UDP_PORT` | `5500` | UDP-порт |
| `ESP32_CSI_WINDOW_SIZE` | `100` | кадров в одном окне |

## Ограничения

- 1 антенна × 52 поднесущие вместо 3×56 у Intel 5300 / Atheros, на которые рассчитаны
  статьи. Предобученной модели под такую форму входа в репозитории нет: `PoseService` пока
  подаёт в модель случайные данные. Следующий шаг — подключить окна из `HardwareService` к
  `PoseService` и обучить или дообучить модель на записях с ESP32.
- Для пространственного разрешения лучше 2–3 платы ESP32 в разных точках комнаты.

## Что сделать дальше (план)

Приёмник (ESP32/Pi) ещё не куплен, поэтому сейчас по пайплайну идут реальные данные роутера
только до `HardwareService`, а `PoseService` подаёт в модель случайный шум. Полный путь:

- [ ] Купить приёмник: ESP32 (уже поддержан в коде) или ESP32-S3/C6 (лучше по качеству CSI),
      либо Raspberry Pi 3B+/4 + `nexmon_csi` (64 поднесущие, качественнее).
- [ ] Прошить приёмник и подключить его к сети `GREENHOME`.
- [ ] В роутере (`http://192.168.8.1`) зафиксировать канал и выставить ширину 20 МГц.
- [ ] Запустить мост и по блоку `csi_receiver` убедиться, что растёт `accepted` и идут кадры
      с MAC роутера.
- [ ] **Соединить `HardwareService` → `PoseService`:** сейчас `estimate_poses` использует
      `np.random.randn(...)`; нужно подать туда реальное окно CSI `get_window()` из роутера.
- [ ] Записать размеченный датасет: скрипт записи окон CSI + синхронная съёмка позы камерой
      для разметки (такого скрипта пока нет).
- [ ] Обучить/дообучить модель под форму входа (1×52 для ESP32, 1×64 для Nexmon).
- [ ] Для пространственного разрешения — 2–3 приёмника в разных точках комнаты.

## Запуск на сервере

- **Мост `esp32_serial_bridge.py`** должен работать на машине, к которой ESP32 подключён по
  USB. Это может быть мини-ПК или Raspberry Pi рядом с роутером, работающий постоянно.
- **API в Docker** можно держать на любом сервере, доступном по `UDP:5500`
  (`ESP32_CSI_UDP_HOST=0.0.0.0`, порт проброшен в `docker-compose.yml`). Если мост и API на
  разных машинах — запускай мост с `--udp-host <адрес_сервера>` и открой `5500/udp` на сервере.
- **Вариант Raspberry Pi + Nexmon:** сама Pi одновременно и приёмник, и «сервер сбора» — она
  может слать строки CSI на API тем же UDP-протоколом (понадобится небольшой адаптер формата
  Nexmon → строка, его в репозитории пока нет).
